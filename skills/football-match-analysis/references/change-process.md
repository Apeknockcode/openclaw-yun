## 同步纪律

- 规则/红线/误区编号**只追加不重排**（现至规则 145 / 红线 157 / 误区 153）
- 基础原文（V3.1）不重写，教训以增量追加；**冲突时以 SKILL.md 规则与核心层 C1-C8 为准**
- **同步后必须跑审计**：grep 各文件最新版本号引用数，确认无滞后——漏同步比不更新更危险
- **容量管理**：SKILL.md 控制 <50KB（理想 <45KB）；超限先把历史详情移入 references
  - V3.49 瘦身：多串主推/筛选器五步→rules.md、规则 71-123 索引→scenarios.md

  - V3.53 瘦身：半全场模块详版→score-prediction.md、复盘同步流程详版→本文件
  - 每批复盘只改对应参考文件，SKILL.md 只改执行索引/核心层/输出格式
- **模块回写体检（V3.53 新增）**：被多批补丁修改的模块类规则（如 129 混合组合模块）**每 3-4 批回写正文一次**——版本纪律「只追加不重排」保持编号稳定，但补丁挂在各自编号下会造成「读模块正文漏补丁」的读取缝（9/14「V3.48 混合串为什么不并入串关建议」=129 正文漏 140③/⑮）→ 回写后模块升小版本号（129 V1.1）

## 技能改动版本控制（2026-09-21 建立 · 本地 git）

**背景**：技能包 1.8MB / 单文件最大 292KB（case-library）→ `skill_workshop`（maxSkillBytes 默认 40KB、支持文件上限 256KiB）**结构性不可用**；改用本地 git 做审计与回滚。

- **仓库**：`/root/.openclaw/workspace`（本地，**不推远程**）；root 操作需 `safe.directory` 白名单
- **基线**：commit `203ab93`（2026-09-21，532 文件）
- **纪律**：**每次技能改动后 commit 一次**，message 写「版本号/批次 + 改动摘要」（如 `V3.59.3: 144 收紧`）；复盘同步与技能改动**同一个 commit**
- **排除**（`.gitignore`）：`wc-profiles/`（登录态）·`node_modules/`·图片/媒体·`tmp*/`·`_deprecated/`·`.backup_*/`·`*.bak*`·敏感关键词
- **审批**：用户口头「改/优化」= 审批；git 只留痕（diff 可查、可回滚），不替代审批
- **回滚**：`git revert <commit>` 或 `git checkout <commit> -- <path>`；**回滚技能后必须同步 memory/ledger 标注**
